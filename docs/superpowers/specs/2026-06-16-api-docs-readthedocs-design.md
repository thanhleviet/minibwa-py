# API Documentation on Read the Docs — Design

Date: 2026-06-16
Status: Approved (design); pending implementation plan

## Goal

Stand up an autogenerated API reference for `minibwa-py`, built with Sphinx and
hosted on Read the Docs. Scope is **API reference plus essentials**: the
generated reference, a landing page, an install page, and a quickstart that
reuse existing `README.md` content.

## Why Sphinx (not MkDocs)

The existing docstrings already commit the project to Sphinx:

- They use Google-style sections (`Args:` / `Returns:` / `Raises:`), which the
  `napoleon` extension parses into structured output.
- They use Sphinx cross-reference roles — `` :func:`map` ``, `` :class:`Index` ``,
  `` :mod:`._cli` `` — which only resolve under Sphinx. MkDocs/mkdocstrings would
  render them as literal text.

So the docstrings are written *for* Sphinx; the task is to wire up the build, not
to rewrite docstrings.

## Decisions (from brainstorming)

| Decision | Choice |
| --- | --- |
| Generator | Sphinx + `autodoc` + `napoleon` + `autosummary` + `intersphinx` |
| Narrative markup | MyST Markdown (`myst_parser`) |
| Theme | Furo |
| Hosting | Read the Docs (`.readthedocs.yaml`) |
| API generation | Hand-written `autoclass`/`autofunction` on the **public** API, not `sphinx-apidoc` |
| Scope | API reference + landing + install + quickstart |

## Public API surface to document

All re-exported from `minibwa/__init__.py` via `__all__`:

- Functions: `index`, `map`, `version`
- Records: `Alignment`, `PafRecord`
- Index handle: `Index`
- Streaming iterators: `SamIterator`, `PafIterator`
- Errors: `MinibwaError`, `MinibwaNotFoundError`, `MinibwaParseError`,
  `MinibwaRunError`

The private modules (`_api`, `_cli`, `_backend`, `_run`, `_locate`, `_tags`) are
**not** documented. Documenting the public names directly (as users import them,
e.g. `minibwa.map`) keeps the internal module layout hidden, matching the
project's deliberate "one hidden seam" design.

## Architecture

### Directory layout

```
docs/
  conf.py            # Sphinx config
  index.md           # landing page + root toctree
  install.md         # pip install; install the engine via bioconda; MINIBWA_BIN
  quickstart.md      # index -> map -> iterate; paired-end; version()
  api/
    index.md         # API reference overview with autosummary tables
    functions.md     # autofunction: index, map, version
    records.md       # autoclass: Alignment, PafRecord
    index_handle.md  # autoclass: Index
    errors.md        # autoclass: the four exceptions
  _static/           # placeholder for future custom CSS
.readthedocs.yaml    # RTD build config
```

### `conf.py`

- `extensions = ["sphinx.ext.autodoc", "sphinx.ext.napoleon",
  "sphinx.ext.autosummary", "sphinx.ext.intersphinx",
  "sphinx.ext.viewcode", "myst_parser"]`
- `html_theme = "furo"`
- `autosummary_generate = True`
- `autodoc_typehints = "description"` so type hints render alongside the
  napoleon-parsed parameter descriptions rather than cluttering the signature.
- `napoleon_google_docstring = True`
- `intersphinx_mapping = {"python": ("https://docs.python.org/3", None)}` so
  stdlib references (`os.PathLike`, `pathlib.Path`, `logging`,
  `collections.abc.Iterator`) become live links.
- Version single-sourced: `release = importlib.metadata.version("minibwa-py")`.
- `nitpicky` stays off (default) so any unresolved external reference is a
  warning, not a hard error — but see Verification: the build must still be
  warning-clean.

### Why no import mocking is needed

`autodoc` imports the package to read its objects. Importing `minibwa` only
configures a `NullHandler` on its logger; it does **not** invoke the engine
binary (that happens at call time inside `map()`/`index()`/`version()`). So the
package imports cleanly on Read the Docs' builders with no engine present and no
`autodoc_mock_imports`.

### Packaging

Add a `docs` optional-dependency group to `pyproject.toml`:

```toml
[project.optional-dependencies]
docs = ["sphinx>=7", "furo", "myst-parser>=2"]
```

Both Read the Docs and local builds install this one group, so there is a single
source of truth for doc dependencies. (`napoleon`, `autosummary`, `intersphinx`,
and `viewcode` ship with Sphinx itself.)

### `.readthedocs.yaml`

```yaml
version: 2
build:
  os: ubuntu-24.04
  tools:
    python: "3.12"
python:
  install:
    - method: pip
      path: .
      extra_requirements:
        - docs
sphinx:
  configuration: docs/conf.py
```

## Cross-reference handling

The public objects' docstrings reference other public objects
(`` :class:`Index` ``, `` :func:`map` ``), all of which are documented, so those
links resolve. The `:mod:` references to private modules live only in the
**module** docstrings of the private modules, which are not rendered, so they
never enter the build. Standard-library references resolve via intersphinx. The
verification step below catches any reference that slips through.

## Verification (success criteria)

1. Local build with warnings-as-errors succeeds:
   `sphinx-build -W -b html docs docs/_build/html` exits 0.
2. The rendered HTML contains pages for every public name listed above with its
   parsed `Args`/`Returns`/`Raises` sections.
3. Iterate on `conf.py` / page sources until the `-W` build is clean.

Final hosting (importing the repo on the Read the Docs dashboard) is a manual
step performed by the maintainer; the install page documents it. It cannot be
automated from here.

## Out of scope (YAGNI)

- PDF / ePub output formats.
- Versioned-docs matrix or multi-version builds.
- Custom CSS / brand theming beyond Furo defaults.
- Changelog, contributing, or full usage-guide pages (those belong to the
  "full documentation site" scope, which was not selected).
- Rewriting or reformatting existing docstrings.

These are all easy to layer on later without reworking the foundation.
